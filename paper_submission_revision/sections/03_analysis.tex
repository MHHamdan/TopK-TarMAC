The bounds below are simple. They place score-then-select, selectors that act
before scoring and fixed patterns on a single axis, the cost of deciding what to
keep, and they give checks a designer can apply before writing a kernel.
Sections~\ref{sec:setting}--\ref{sec:ceiling} bound what sparsity can remove,
Section~\ref{sec:escape} charges the selector, and Section~\ref{sec:roofline}
gives a screen for whether a reduction can become time.

\subsection{Setting and implementations}
\label{sec:setting}

Consider one round of scaled dot-product attention over $N$ agents, per batch
element and head, at head width $d$. Agent $i$ forms a query $q_i$; every agent
contributes a key and a value; self-attention is masked. Write
$s_i = q_i K^\top \in \mathbb{R}^N$ for the score vector and
$a_i = \mathrm{softmax}(s_i)$, so that dense attention computes $m_i = a_i V$. A
top-$k$ variant keeps the $k$ largest entries of $a_i$ and renormalises over
them. We call a rule that forms the complete score vector and then keeps its
$k$ largest entries \emph{score-then-select}. The ceiling of
Section~\ref{sec:ceiling} concerns that class only, not content-dependent
selection in general; Section~\ref{sec:escape} treats selection before scoring.

Attention has two matrix products of equal size: one produces the pairwise
scores and the other aggregates the values. Restricting the retained set shrinks
the second, because only $k$ value rows are combined, and cannot shrink the
first, because the scores are what the selection reads. The same top-$k$
function also admits several implementations (Figure~\ref{fig:taxonomy}), and
whether the saving is executed depends on which one runs.

\begin{description}
  \item[Masked top-$k$] multiplies the dense weights by a $\{0,1\}$ mask and
    renormalises. The discarded entries are materialised as zeros and
    multiplied, so the executed aggregation is that of dense attention.
  \item[Gathered top-$k$] takes the top-$k$ of the raw scores, applies a
    softmax over those $k$ values, gathers the corresponding value rows into a
    $(B,N,k,d)$ tensor and contracts it. Here the aggregation does shrink.
  \item[Fused top-$k$] computes the same function in one kernel, holding the
    score row on chip, selecting within it and accumulating the weighted values
    without writing a score matrix, an index tensor or a gathered tensor to
    memory (Section~\ref{sec:fused}).
\end{description}

\begin{figure}[t]
\centering
\includegraphics[width=\linewidth]{figures/fig1_taxonomy.pdf}
\caption{What each kind of peer selection removes and what it still pays for,
per batch element and head. Box colour gives the role of a stage; widths
indicate the kind of term, not measured time. Every score-then-select variant
forms all $N^2$ scores before it can rank them, so at most the aggregation can
shrink: the masked variant multiplies the discarded weights as zeros, the
gathered one removes them but writes and re-reads a compacted tensor, and only
the fused one removes them without adding traffic. Selecting before scoring
removes score and aggregation terms alike, at the price of the selector. The
threshold kernel of Section~\ref{sec:fused} is fused but keeps the dense
aggregation.}
\label{fig:taxonomy}
\end{figure}

Gathered and masked top-$k$ compute the same function, since softmax is
monotone within a row and a softmax over the $k$ retained scores equals the
dense softmax restricted to them and renormalised; all implementations we time
agree to floating-point tolerance (Appendix~\ref{app:verification}).

\subsection{An operation-count ceiling for score-then-select}
\label{sec:ceiling}

We count multiply--accumulates (MACs) of the two attention products and exclude
the input and output projections shared by every implementation:
\begin{equation}
C_{\text{dense}} = \underbrace{N^2 d}_{\text{scores}} +
\underbrace{N^2 d}_{\text{aggregate}}, \qquad
C_{\text{top-}k} = \underbrace{N^2 d}_{\text{all scores}} +
\underbrace{Nkd}_{\text{aggregate }k}.
\label{eq:counts}
\end{equation}

\begin{proposition}[Score-then-select ceiling]
\label{prop:ceiling}
Let the retained set be fixed by a score-then-select rule, one whose kept
indices are determined only after the complete score vector of each query has
been formed, and let keys and values have equal width. Then, for the forward
pass,
\begin{equation}
\frac{C_{\text{dense}}}{C_{\text{top-}k}}
= \frac{2N}{N+k} < 2 \qquad \text{for all } k \ge 1,
\end{equation}
with supremum $2$ approached only as $k/N \to 0$.
\end{proposition}

The saving an operation count suggests for top-$k$ communication,
$1 - k/(N-1)$, describes the aggregation term alone. Read as the saving of the
mechanism, it overstates the achievable reduction by exactly a factor of two
(under the masked-diagonal count the removable fraction is
$\tfrac12(1 - k/(N-1))$), and this is before any question of whether the
reduction is realised in time. The bound depends only on \emph{when} the
retained set is fixed, since a rule that reads every score must first compute
every score. The observation is not new in kind: \citet{chen2023dfss} bound the
speedup of top-$k$ attention by a constant in a memory-access model even when
the mask is supplied at no cost. Proposition~\ref{prop:ceiling} states the
limit as a closed-form operation count, extends it to training, and serves as
the limiting case of the selector accounting below.

The proof, the treatment of the masked diagonal and seven assumptions are in
Appendix~\ref{app:theory}. The assumptions are a single round, full-score
selection, a per-head count, projections excluded, selection cost excluded,
equal key and value widths, and element-wise work excluded. Relaxing the
single-round, per-head, projection or selection-cost assumption leaves the ratio
unchanged or moves it closer to one. Values wider than keys raise the ceiling to
$1 + d_v/d_k$, and charging the softmax can lift it slightly above two.

The proposition concerns the forward pass. In training, exact selection is piecewise constant in the scores,
so a backward written for it needs the gradient products only over the retained
pairs, and the analogous bound is $6N/(N+5k) < 6$; the autograd backward we
time forms dense query and key gradients and does not reach it
(Appendix~\ref{app:theory}). Every timing claim in this paper concerns the
forward pass unless stated otherwise.

\subsection{Selection before scoring}
\label{sec:escape}

Mechanisms that are content-dependent but do not read the complete score vector
lie outside Proposition~\ref{prop:ceiling}: nearest-neighbour retrieval,
clustering, routing, hashing and fixed patterns can identify candidates without
forming every score \citep{kitaev2020reformer,roy2021routing,yuan2025nsa}. What
they pay instead is the cost of deciding, and SCALE charges it explicitly.

\begin{proposition}[Selection before scoring]
\label{prop:escape}
Suppose the retained set is determined without forming the complete score
vector, at total selector cost $C_{\mathrm{sel}}(N,k,d)$, and that scores are
then evaluated only for the $Nk$ retained pairs. Then
\begin{equation}
S \;=\; \frac{C_{\text{dense}}}{C_{\mathrm{pre}}}
  \;=\; \frac{2N^2 d}{2Nkd + C_{\mathrm{sel}}}.
\end{equation}
(i) Along any sequence with $N \to \infty$, $k$ and $d$ allowed to depend on
$N$: if $C_{\mathrm{sel}} = o(Nkd)$, then $S/(N/k) \to 1$; equality with $N/k$
holds only for $C_{\mathrm{sel}} = 0$. (ii) If $C_{\mathrm{sel}} = o(N^2 d)$
and $k/N \to 0$, then $S$ diverges, though not in general at the rate $N/k$.
\end{proposition}

A score-then-select rule is the limiting case. It has formed every score while
selecting, so written in this form its selector cost is at least the scores of
the discarded pairs, $C_{\mathrm{sel}} \ge N^2 d - Nkd$, and substituting
recovers Proposition~\ref{prop:ceiling}. The two propositions therefore place
every peer-selection mechanism on one axis, the cost of deciding what to keep,
and the position on that axis bounds what the mechanism can save.

\begin{corollary}[What a selector costs, and what it can buy]
\label{cor:taxonomy}
Count $C_{\mathrm{sel}}$ in MAC-equivalents of two scalar operations each, so
that a comparison or integer operation is half a unit. Fix $k$ and $d$ and let $N \to \infty$.
\emph{(a) Full-score selection}, $C_{\mathrm{sel}} \ge N^2 d - Nkd$: $S < 2$.
\emph{(b) All-pairs selection in a feature space of dimension $p$},
$C_{\mathrm{sel}} = \gamma N^2 p$: $S \to 2d/(\gamma p)$, a constant.
\emph{(c) Sub-quadratic selection}, $C_{\mathrm{sel}} = \Theta(N \log N)$:
$S = 2Nd/(2kd + \Theta(\log N)) = \Theta(N/\log N)$, unbounded but a
vanishing fraction of $N/k$.
\emph{(d) Linear selection}, $C_{\mathrm{sel}} = cNkd$ for a constant $c>0$:
$S = 2N/((2+c)k)$ exactly; and $S \sim N/k$ when $C_{\mathrm{sel}} = o(Nkd)$, as for a
fixed or precomputed pattern.
\end{corollary}

Only a free selector delivers the $N/k$ that operation-count arguments for
sparse communication invoke, and full-score selection is bounded by two at
every $N$. Multi-agent methods sit between these extremes, and the intermediate
cases differ. A selector that ranks all pairs in a feature space of per-pair
cost $\gamma p$ is capped at $2d/(\gamma p)$, which exceeds two only when
$\gamma p < d$, whereas a sub-quadratic selector is unbounded. The lightning
indexer of DeepSeek Sparse Attention is a large-scale instance of
case~(b): it scores every query--key pair with a cheaper function, and its
authors note that it remains quadratic \citep{deepseek2025v32}. The asymptotic
classes do not depend on the unit convention; the constants in the closed forms of
Appendix~\ref{app:closedforms} do. Proofs are in Appendix~\ref{app:theory}.

\subsection{Why the count need not govern the time}
\label{sec:roofline}

For memory-bound kernels, time tracks bytes moved rather than arithmetic
performed \citep{williams2009roofline}. At head width $16$, the two composed
paths in this study have an arithmetic intensity below every machine balance we
measure on the same device (Appendix~\ref{app:intensity}), so their accounting
is of bytes; fused kernels, which never write the score matrix, are not covered
by this argument. For the composed paths, gathering moves memory traffic
instead of removing it: in place of multiplying $N-k$ zeros, the gathered path
writes and re-reads a compacted $(B,N,k,d)$ tensor and the indices that build
it.

\paragraph{Byte criterion.} Count each tensor read or written once, in fp32
with int64 indices. Replacing the dense softmax and aggregation by selection, a
softmax over $k$, the gather and the compacted contraction changes traffic by
$2Nkd + 8Nk - 2N^2$ elements per batch element. The dominant terms compare two
intermediates: the compacted tensor, written and re-read, costs $2kd$ per query,
whereas the dense weight row, written and re-read, costs $2N$. Gathering is
therefore byte-neutral only if $k(d+4) \le N$, to leading order $kd \le N$.

At $d{=}16$ and $N{=}512$ the leading-order form admits $k \le 32$ ($k \le 25$
exactly); at $d{=}128$, $k \le 4$ ($k \le 3$). Unlike the operation count, the
criterion depends on $d$, and it can be checked before any code is written.
With int32 indices the index term halves and the exact
condition becomes $k(d+2) \le N$; in a narrower value format the index term
grows relative to the rest. The leading-order form is unchanged in every case,
and the composed path cannot use int32 in any event, since PyTorch's gather
takes int64 indices.

The criterion is a screen under a simplified accounting that ignores caches and
fusion; it is not a model of GPU time. It also counts selection as one read of
the scores, whereas hardware counters on two GPUs show that a library top-$k$
reads them several times (Appendix~\ref{app:portability}). Under this
accounting, passing the screen is necessary for a composed gathered path to win
but not sufficient.

\paragraph{What the accounting predicts.} Before any kernel is written, SCALE
gives upper bounds (below two for score-then-select, a constant for an
all-pairs selector), the asymptotic ordering of the selector classes, and a
traffic screen for compaction. It does not give constants, the ordering of
selectors at the agent counts we measure, or the behaviour of kernels whose
time is dominated by fixed per-launch cost. Section~\ref{sec:measurement}
tests the three predictions: the ceiling against executed operation counts
(Section~\ref{sec:composed}), the byte screen against the composed path
(Section~\ref{sec:latency}), and the class ordering against three selectors
(Section~\ref{sec:prescore}).
