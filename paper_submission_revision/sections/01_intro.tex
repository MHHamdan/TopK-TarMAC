Cooperative multi-agent systems increasingly exchange learned messages, and
attention is a common way of deciding whose message matters
\citep{das2019tarmac,jiang2018atoc,jiang2018dgn}.\footnote{\LLMDisclosure}
Attention over $N$ agents is pairwise, so its cost grows quadratically, and
several methods restrict who attends to whom, citing communication or
computational cost among their reasons
\citep{jiang2018dgn,sun2020sparsecomm}. The computational
argument is an operation count: if each agent aggregates messages from $k$ peers
instead of $N-1$, the aggregation shrinks by a factor of about $N/k$.

This paper asks when that saving becomes elapsed time. Three costs have to be
separated, and an operation count conflates them. The first is \emph{what can
be removed at all}: a rule that selects peers by their attention scores needs
the scores, so every pairwise score has been computed by the time the selection
is made, and only the aggregation can shrink. The second is \emph{what the
implementation executes}: masking the discarded weights to zero leaves the
dense multiplication in place, while gathering the retained values removes it
and writes new intermediates instead. The third is \emph{what the hardware
spends its time on}: at the agent counts and head widths of this setting,
attention composed from library operators is memory-bound, so an implementation
that removes arithmetic while adding data movement can become slower, and inside
a fused kernel the comparisons of selection can cost more than the arithmetic
they remove. We study centralised inference on a
single device, the setting in which the methods we cite are trained and
evaluated, and not bandwidth-constrained distributed deployment, such as
multi-agent orchestration across edge devices \citep{marliotp2026}, where
reducing transmitted messages is itself the objective.

The object of the paper is that accounting rather than any one mechanism. Most
multi-agent methods that restrict communication choose peers before scoring
them, from positions, per-agent gates or a separate network
(Section~\ref{sec:related}). \emph{Score-then-select}, which ranks the attention
scores themselves, is uncommon in this literature, and the cost argument made for
it is a reduction in complexity \citep{sun2020sparsecomm}, so this paper does not
set out to correct a measured result. We treat it as the limiting case of
\emph{SCALE} (Selector-Cost Accounting for Latency Evaluation), an accounting
that charges every rule for the cost of deciding what to keep, and measure each
case with a protocol built for kernels that run for microseconds.

\paragraph{Findings.} For \emph{score-then-select} rules, which form every score
before keeping the $k$ largest, at most half of the forward-pass attention
multiply--accumulates are removable at any sparsity, a limit noted before in a
memory-access model \citep{chen2023dfss}. Composed from library operators, such
a rule is slower than dense attention at every agent count and sparsity we
measure on four GPUs, the gathered form by up to thirty-seven times, because of
memory traffic. Fused kernels that hold each query's score row on chip are
faster with one retained peer, and with two in a single configuration. A kernel
that streams the selection through a running candidate set is faster in fp32
with one retained peer on all four GPUs; with two and four the outcome depends
on the GPU, from faster with two and close to parity with four on the Blackwell
card to slower with four on the A100, H100 and H200. In every kernel most of
the time from $384$ agents upward is spent finding the retained set. In bf16,
which accelerates the products and not the selection, the streaming kernel is
near parity with one retained peer on the Blackwell card and slower than dense
attention on the other three. Rules that \emph{select before scoring}
escape the bound: attention over a pre-selected set is up to sixteen times
faster than dense attention on the Blackwell card and \PortPreAttnLo{} to
\PortPreAttnHi{} times on the other three, and the selector then decides the outcome, with
only the cheapest of three reaching parity end to end, at $512$ agents and on
the Blackwell card only. Below a hundred agents, where the methods we cite are
evaluated, none of this governs latency on any of the four GPUs: the number of
kernels a communication step launches does.

\paragraph{Contributions.}
\begin{itemize}
  \item SCALE, a selector-cost accounting (Section~\ref{sec:analysis}) that charges
    every peer-selection rule for deciding what to keep and sorts mechanisms
    into four asymptotic classes (Proposition~\ref{prop:escape},
    Corollary~\ref{cor:taxonomy}). Its limiting case, score-then-select, has a
    closed-form multiply--accumulate limit for the forward and backward passes
    (Proposition~\ref{prop:ceiling}), and a byte criterion, $kd \le N$, screens
    compaction before implementation.
  \item SCALE's measurement protocol for microsecond-scale attention kernels
    (Section~\ref{sec:measurement}): masked, gathered and fused implementations
    of one function, verified equivalent, timed interleaved against the best of
    a vendor library, FlexAttention and a dense kernel searched over the sparse
    kernels' parameter space, in three numerical formats; a fixed-set comparison
    that separates finding the retained peers from using them; and a checklist of
    eight errors that each produced a plausible but spurious result
    (Section~\ref{sec:checklist}).
  \item Using SCALE, a characterisation, on four GPUs across three generations, of when
    the arithmetic removed by exact top-$k$ attention between agents becomes
    wall-clock time (Sections~\ref{sec:fused}--\ref{sec:smalln},
    Appendix~\ref{app:portability}). The crossover is governed mainly by the
    cost of selection, which takes most of a fused score-then-select kernel's
    time, and it moves with the retained count, the numerical format and the
    GPU: in fp32 one retained peer is faster than dense attention on every GPU
    we measured, more than one only on some, and in bf16 one retained peer is at
    best near parity, on the Blackwell card only.
    Selection before scoring pays end to end only when the selector is cheap in
    absolute terms, which we observed on one of the four GPUs.
\end{itemize}
