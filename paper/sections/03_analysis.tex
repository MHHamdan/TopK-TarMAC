\subsection{Setting and three implementations of one function}
\label{sec:three}

Consider one round of scaled dot-product attention over $N$ agents, per batch
element, with head width $d$. Agent $i$ forms a query $q_i$, and every agent
contributes a key and a value; self-attention is masked. Write
$s_i = q_i K^\top \in \mathbb{R}^N$ for the score vector and
$a_i = \mathrm{softmax}(s_i)$ for the attention weights. Dense attention
computes $m_i = a_i V$.

A top-$k$ variant keeps only the $k$ largest entries of $a_i$ and renormalises.
The same function admits implementations with very different costs, and the
distinction between them is the one this paper turns on.

\begin{description}
  \item[Masked top-$k$.] Compute $a_i$ in full, multiply by a $\{0,1\}$ mask,
    renormalise, and evaluate $m_i = \tilde{a}_i V$ with $\tilde{a}_i$ still
    dense in memory. The discarded entries are materialised as zeros. Executed
    multiply--accumulates are identical to dense, plus the cost of selection
    and masking.
  \item[Gathered top-$k$.] Take the top-$k$ of the raw scores, softmax over
    those $k$ values only, gather the corresponding value rows into a
    $(B,N,k,d)$ tensor, and contract
    $(B\!\cdot\!N,1,k)\times(B\!\cdot\!N,k,d)$. No zeros are materialised and
    the aggregation genuinely shrinks.
  \item[Fused dense.] Compute the same function as dense through a fused kernel
    \citep{dao2022flashattention,rabe2021selfattention} that never
    materialises the $(B,N,N)$ weight matrix.
\end{description}

\begin{figure}[t]
\centering
\includegraphics[width=\linewidth]{figures/fig1_schematic.pdf}
\caption{The same top-$k$ attention, computed three ways. All three form the
full score matrix, because selecting peers by score requires every score. They
differ in what happens next: the fused kernel never materialises the weights;
the masked variant stores the discarded entries as zeros and multiplies them
anyway, so its executed operation count equals dense; only the gathered variant
compacts the kept rows and shrinks the product. The efficiency argument
examined in this paper is an argument about the third row.}
\label{fig:schematic}
\end{figure}

Figure~\ref{fig:schematic} sets the three side by side. Gathered and masked
top-$k$ compute the same function: softmax is monotone within a row, so the
top-$k$ weights are the top-$k$ scores, and a softmax over just those $k$
scores equals the dense softmax restricted to them and renormalised. We verify
agreement to $<10^{-10}$ in \texttt{float64} and pin it with a regression test
(Appendix~\ref{app:verification}). The operation-count argument is about the
gathered variant; timing the masked variant measures an implementation
artifact, and timing either against unfused dense alone ignores what a
production kernel costs. We therefore report all three throughout, each against
both dense baselines.

\subsection{A ceiling on what sparsity can save}
\label{sec:bound}

Counting multiply--accumulates in the two matrix products that constitute
attention, and excluding the shared input and output projections:
\begin{equation}
C_{\text{scores}} = N^2 d, \quad C_{\text{agg}} = N^2 d, \quad
C_{\text{dense}} = 2N^2 d, \qquad
C_{\text{top-}k} = \underbrace{N^2 d}_{\text{all scores}} + \underbrace{Nkd}_{\text{aggregate }k}.
\end{equation}

\begin{proposition}[Ceiling]
\label{prop:ceiling}
For any selection rule that requires the complete score vector of each query,
\begin{equation}
\frac{C_{\text{dense}}}{C_{\text{top-}k}}
= \frac{2N^2 d}{N^2 d + Nkd} = \frac{2N}{N+k} < 2
\qquad \text{for all } k \ge 1,
\end{equation}
with supremum $2$ approached only as $k/N \to 0$. No choice of $k$ or $N$
yields more than a $2\times$ reduction in attention FLOPs.
\end{proposition}

\begin{proof}
$C_{\text{top-}k} > N^2 d = \tfrac12 C_{\text{dense}}$ for every $k \ge 1$
since $Nkd > 0$. The ratio decreases monotonically in $k$ and tends to $2$ as
$k/N \to 0$.
\end{proof}

We use $N^2d$ rather than $N(N{-}1)d$ because it is the count the
implementations actually execute: self-masking is applied by writing $-\infty$
into the diagonal of a full $N \times N$ score matrix, not by skipping work.
Counting the masked-out diagonal exactly instead would give
$2(N{-}1)/\bigl((N{-}1)+k\bigr)$, which is strictly smaller than $2N/(N+k)$ for
every $1 \le k \le N-1$. Proposition~\ref{prop:ceiling} is therefore a valid
upper bound under either convention, and a slightly loose one under the exact
count. The figure $1 - k/(N-1)$, which describes the aggregation term alone,
is at most half of attention; read as \emph{the} saving it overstates the
achievable reduction by a factor approaching two, before any question of
whether it is realised in time.

The assumptions are worth separating, because only one of them is
load-bearing. \textbf{(A1) Single round}: with $R$ rounds both terms scale by
$R$ and the ratio is unchanged. \textbf{(A2) Data-dependent selection}: the
kept set is a function of the scores, so all $N$ scores must be formed.
\textbf{(A3) Per head}: with $H$ heads of width $d/H$ both terms scale
identically. \textbf{(A4) Projections excluded}: including the shared $qkv$ and
output projections moves the ratio strictly closer to $1$, so the bound
remains valid. \textbf{(A5) Selection cost excluded}: counting the top-$k$
operation itself can only decrease the ratio, and Section~\ref{sec:decomp}
shows this term is large in practice.

A2 is the assumption that carries the result. It is a statement about a class
of selection rules, not about sparsity in general, and when it fails the
ceiling lifts.

\begin{proposition}[Escape]
\label{prop:escape}
If the kept set is determined \emph{structurally} --- by information obtainable
without forming the scores, in $o(N^2 d)$ --- then scores need not be computed
for discarded pairs, and
$C_{\mathrm{struct}} = Nkd + Nkd = 2Nkd$, giving
$C_{\text{dense}}/C_{\mathrm{struct}} = N/k$, which is unbounded in $N/k$.
\end{proposition}

Qualifying rules include a fixed communication topology, a spatial or distance
prior, a locality-sensitive hash, and a learned \emph{static} graph. This is
why Longformer and BigBird obtain asymptotic savings where data-dependent
top-$k$ cannot \citep{beltagy2020longformer,zaheer2020bigbird}: their patterns
are fixed before any score is formed. It is also the concrete design target for
a successor method --- to exceed $2\times$, a method must decide where to look
before looking. In an environment with spatial structure a distance-calibrated
selector is the obvious candidate.

Proposition~\ref{prop:escape} concerns operation counts only. It says that
structural selection removes the assumption responsible for the ceiling; it
does not say that any particular structural method attains a proportional
speedup, which is a separate question and one the rest of this paper suggests
should be asked separately.

\subsection{Why the ceiling is not the binding constraint}
\label{sec:roofline}

Proposition~\ref{prop:ceiling} bounds a quantity that, in this regime, does not
govern runtime. For memory-bound kernels time tracks bytes moved rather than
arithmetic performed \citep{williams2009roofline}, and the two paths differ far
more in bytes than in FLOPs.

We compute arithmetic intensity $\mathrm{AI} = \text{FLOPs} / \text{bytes}$
analytically per stage, counting each tensor read and written once, and compare
it against a \emph{measured} machine balance: a large GEMM gives achievable
FLOP/s, a large device-to-device copy gives achievable bandwidth, and their
ratio is the ridge point above which a kernel is compute-bound. Two caveats
apply to this model and we state them before using it. Counting each tensor
once ignores cache residency, so at small $N$ --- where the whole working set
fits in the GPU's $128$\,MB L2 --- the analytic byte counts overstate traffic
and the model does not apply. And our CPU bandwidth probe uses buffers smaller
than the host's $96$\,MiB L3, so the CPU ridge is a cache-bandwidth figure and
is not reproducible to better than a factor of a few: repeated measurement of
the same host gives $1.35$ and $3.68$\,FLOP/byte on different days, and a
DRAM-resident probe gives lower still. We therefore use the CPU ridge only for
statements that hold across that whole range, and the dense path's saturating
intensity of $4.31$ is above all of them.

Table~\ref{tab:roofline} and Figure~\ref{fig:roofline} give the result. The
gathered path adds two stages that move substantial memory for no arithmetic
--- the top-$k$ selection and the gather --- so its intensity is pinned near
$0.66$ and does not improve with $N$. Dense intensity, by contrast, rises towards $(4d{+}5)/16 = 4.31$. At $N{=}512$ the sparse path moves $4.16$\,GB to perform
$2.76$\,GFLOP, against dense's $1.11$\,GB for $4.63$\,GFLOP: $3.8\times$ the
traffic for $0.6\times$ the arithmetic.

Where the model's assumptions hold it predicts well. At $N \in \{192, 512\}$,
where the working set exceeds L2 and traffic is real, both paths attain a
substantial fraction of achievable bandwidth and the ratio of analytic bytes
tracks the ratio of measured latencies. At $N \le 48$ it does not
apply, and Section~\ref{sec:threecurves} shows those cells are governed by
kernel launch count instead.

The quantity this analysis bounds is a ratio of intensities --- roughly $0.16$
at large $N$ --- which is a property of the two algorithms rather than of any
device constant, so the qualitative disadvantage should be expected to persist
wherever the gathered path stays below the relevant machine balance. That is
not by itself evidence that it does: an argument constructed to be
device-independent cannot demonstrate device-independence.
Section~\ref{sec:cpu} supplies measurements on a second architecture, and
Section~\ref{sec:limitations} states what they establish.
